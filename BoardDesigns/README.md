This directory contains the design files for the various PCBs and mechanical components.

Tools needed to build the boards

*   KiCad 10 (the boards are saved by KiCad 10; `kicad-cli` ships inside it)
*   Python 3 with Pillow, for trimming the renders
*   CMake 3.15 or later
*   KiBot, only if you want to run the fabrication configurations by hand

Tools needed to build base adapter plastic

*   openscad

Boards are grouped by role; each board is `<Group>/<board>/`:

* Tags/ -- the animal-borne tags themselves (BitTag, PresTag, CompassTag, IMUTag, ...);
  superseded tag variants are in Tags/Obsolete/
* Bases/ -- boards a tag plugs into: tagbase-* production baseboards and the MCU-carrying tag-breakout-* boards
* Prototypes/ -- tag circuits laid out as breakouts, ST eval daughter cards, imutag-daughtercard, UIUCBreakout
* Chargers/ -- MultiCharger and its JLCPCB variant
* Development/ -- bench and test equipment (TagPwrMonitor, js320-faceplate)

Shared infrastructure stays at this level: libraries/, kicad_libraries/,
kicad-helpers/, Kibot-config/, Templates/. Older retired boards live in Obsolete/.
Board files reach these through `${KIPRJMOD}/../../`, so moving a board to a
different depth means rebasing its lib tables, 3D-model paths, kibot include
and datasheets symlink.

## Generating schematic PDFs and board images

CMake generates two figures per documented board, both with `kicad-cli`:

| Figure | Written to | Drawn from |
| --- | --- | --- |
| Schematic PDF | `docs/src/schematics/<board>.pdf` | every `*.kicad_sch` in the board directory |
| 3D render, top | `docs/src/images/boards/<board>-top.png` | `<board>.kicad_pcb` |
| 3D render, bottom (tags only) | `docs/src/images/boards/<board>-bottom.png` | `<board>.kicad_pcb` |

They are written into the source tree and committed, because the site's
publishing workflow has no KiCad. Configure from the repository root:

```sh
cmake -S BoardDesigns -B build-boards
```

then build one of these targets:

| Target | Does |
| --- | --- |
| `board-docs` | PDFs and renders for every board whose sources changed |
| `board-schematics` | the schematic PDFs only |
| `board-renders` | the 3D renders only |
| `<board>-schematic` | one board's PDF, e.g. `CompassTag-schematic` |
| `<board>-renders` | one board's renders, e.g. `CompassTag-renders` |

```sh
cmake --build build-boards --target board-docs
cmake --build build-boards --target CompassTag-renders
```

None of them is part of the default build, so a plain `make` never rewrites
committed files. Only boards whose sources changed are redrawn; each render
takes about 45 seconds of raytracing, the PDFs almost nothing.

What the rules do:

* **PDF** — `kicad-cli sch export pdf --no-background-color`, so it prints on
  white whatever colour scheme the schematic is edited in. A hierarchical
  design exports every sheet into one file, and editing any sheet triggers a
  re-export.
* **Renders** — `kicad-cli pcb render --rotate 0,0,90 --zoom 0.5 --width 2400
  --height 2400 --quality high --preset follow_pcb_editor --background
  transparent`, then `kicad-helpers/fit_render.py` trims the image to the
  board and turns it portrait. Tags are drawn from both sides; bases and
  prototype carriers from the top only.
* **Stamps** — after each figure, the SHA-256 of its sources is written to
  `BoardDesigns/.render-stamps/` (`<board>.sha256`, `<board>.sch.sha256`), so
  `kicad-helpers/check_renders.py` can tell a stale figure without KiCad.

Configure prints the settings in force — check it:

```
-- kicad-cli: /Applications/KiCad/KiCad.app/Contents/MacOS/kicad-cli
-- Board renders: zoom 0.5, frame 2400 square, preset follow_pcb_editor
```

Override for an experiment with `-DRENDER_ZOOM=`, `-DRENDER_FRAME=` or
`-DRENDER_PRESET=`; if `kicad-cli` or Pillow is not found, point at them with
`-Dkicad_cli_EXECUTABLE=` or `-DPython3_EXECUTABLE=`.

Before regenerating, run `python3 BoardDesigns/kicad-helpers/check_models.py` —
`kicad-cli` silently draws a missing 3D model as nothing.

### Adding a board

Give the board directory a one-line `CMakeLists.txt` naming the `.kicad_pcb` /
`.kicad_sch` basename:

```cmake
add_board_renders(CompassTag)          # tags: top and bottom
add_board_renders_top(tagbase-v7)      # bases and prototypes: top only
```

and list it with `add_subdirectory(<Group>/<board>)` in
`BoardDesigns/CMakeLists.txt`. Boards not listed there get no targets.

### Fabrication outputs

Gerbers, BOM and CPL are no longer generated by CMake (the old
`<board>-pcb` targets are gone). Export them from KiCad's fabrication plugins,
or run the KiBot configurations in `Kibot-config/` by hand.

[`REGENERATING.md`](REGENERATING.md) has the full story: the checks that guard
the figures, what each of their messages means, and why the framing is set the
way it is.
