# BitPresTag: OpenSCAD → parametric FreeCAD

Generated by `bitprestag_param.py` → `BitPresTag-param.FCStd`.
Source of truth for geometry: `BitPresTag.scad`.

## Document structure

| Object | What it is |
|---|---|
| `params` | Spreadsheet. Every dimension, aliased. Derived values are formulas. |
| `BaseBody` | PartDesign Body — the base, 12 features |
| `LidBody` | PartDesign Body — the lid, 6 features |
| `base_engraving`, `lid_engraving` | Extruded ShapeString cutters, fused |
| **`Base`, `Lid`** | **The finished parts** (`Part::Cut` of body − engraving) |

Every sketch is attached to its body's XY plane with `AttachmentOffset.Base.z`
bound to an expression, is **fully constrained**, and has every driving
constraint named (`blk_len`, `n_cx`, `ep_wid`, …) and bound to a `params`
alias. Pad/Pocket lengths are bound too. So nothing is a hard-coded number
below the spreadsheet.

Coordinates match the `.scad`: XY board-centered, Z = 0 at the board underside.
The base spans z = −5.57 … +1. The lid is drawn lifted by `lid_preview_z`
(default 10, as in `makeLid()`); set it to 0 to see the parts assembled.

## Two levels of parameterization

**Live** — edit a `params` cell, the model recomputes. This includes `name`:
`ShapeString.String` is expression-bound, so both engravings re-render.
Verified live: `board_nominal_len` 18→24 and `board_nominal_width` 10→13
propagate correctly through `base_len`, the harness slots, `lid_body_x`,
`lid_body_len` and both lid end blocks; `pogo_center_x` 6.4→8 and
`lid_end_len` 2→3 move the pogo window, posts, battery pocket and the lid end
block together; renaming updates both engravings. No recompute errors.

**Script-time** — feature topology, and the CLI flags:

```
freecadcmd bitprestag_param.py                      # rebuild the .FCStd
freecadcmd bitprestag_param.py -- --stl             # + BitPresTag-fc-{base,lid}.stl
freecadcmd bitprestag_param.py -- --base-only
freecadcmd bitprestag_param.py -- --set board_nominal_len="22 mm"
freecadcmd bitprestag_param.py -- --params variant.json
```

`--params` takes a JSON dict of `alias: content`, so a tag variant can be a
data file rather than an edited script. Inside the GUI:
`exec(open('bitprestag_param.py').read())`.

## Key parameters

| | |
|---|---|
| Identity | `name`, `marker`, `font_file` |
| Board | `board_nominal_len`, `board_nominal_width`, `board_edge_clearance`, `board_sweep_height`, `under_board_ledges`, `under_board_cut_depth` |
| Pogo pins | `pogo_center_x/y`, `pogo_cutout_len/width`, `pogo_pin_full_height`, `pogo_pin_board_inset` |
| Posts | `post_offset_from_pogo`, `post_spacing`, `post_radius`, `insert_hole_radius`, `screw_hole_radius` |
| Lid ends | `lid_end_len`, `lid_end_height`, `lid_end_width`, `lid_left_end_inset`, `lid_left_end_width`, `lid_left_end_drop`, `lid_body_inset`, `lid_body_len_trim` |

Positions that were bare literals in the `.scad` are now named:
`post_offset_from_pogo` (−5), `lid_left_end_inset` (1.5), `lid_body_inset`
(0.5), `lid_body_len_trim` (1.1 = the `.scad`'s 0.7 + 0.4),
`lid_left_end_drop` (2), `pogo_pin_board_inset` (0.7).

## Verification against the OpenSCAD output

Compared the generated solids against `BitPresTag-base.stl` /
`BitPresTag-lid.stl` by vertical-ray column integration on a 0.15 mm grid —
the symmetric difference per column, not just total volume.

| | Base | Lid |
|---|---|---|
| OpenSCAD volume | 2678.166 mm³ | 858.989 mm³ |
| FreeCAD volume | 2678.085 mm³ | 858.894 mm³ |
| Bounding box | identical | identical |
| Differing columns | 348 / 30 102 | 550 / 18 338 |
| …exceeding engraving depth | **0** | **0** |

Every difference is one of two things: a per-column thickness difference at or
below the engraving depth (0.4 / 0.5 mm) where the glyph outlines differ, or a
full-thickness difference in 3 grid columns landing exactly on a cylindrical
silhouette (r = 3 at the post bosses) — a sampling artifact. Nothing falls in
between, which is the signature that no feature is misplaced or mis-sized.

The glyph differences are expected: OpenSCAD defaults to Liberation Sans,
which isn't installed here, so `font_file` defaults to Arial. Point it at a
Liberation Sans TTF for byte-level parity of the engraving.

## Three faithful-but-odd behaviors carried over

1. **The base `*` marker cuts nothing.** `base_marker_z` evaluates to
   `board_sweep_height/2 − 0.4` = 1.6 mm, above the base top face at +1 mm, so
   the glyph floats clear of the part. That is what the `.scad` does too. To
   actually engrave the pocket floor, set `base_marker_z` to
   `=-under_board_cut_depth + 0.4 mm`.
2. **The harness-slot end fillets were dropped.** The `.scad` added two
   `harness_slot_radius` cylinders at `(+harness_slot_x, ±base_width/2)`; they
   sit entirely at or outside the base wall, so they removed no material. They
   also overlap the slot rectangle, which PartDesign rejects as a
   self-intersecting profile. The slots are instead cut `2·eps` longer in Y so
   the cut faces aren't coplanar with the base walls — geometrically identical,
   more robust in OCC.
3. **The lid version string overhangs the lid body in Y.** At `text_size` 2 the
   string is ~12.8 mm long and rotated −90°, while the lid body is
   `board_width` ≈ 10.1 mm wide. As in the `.scad`, the ends of the engraving
   run off the part.

Two other deliberate substitutions, both verified equivalent: the reinforced
post crossbar is three pads (`post_boss_main`, `post_boss_aux`, `post_web`)
rather than one sketch, because the two bosses and the web overlap; and the
finite through-extrusions in the `.scad` (pogo window, alignment pins, insert
holes) are `ThroughAll` + `Midplane` pockets, which stay correct if the base
gets taller.

## Why the engraving is a `Part::Cut` and not a Pocket

A ShapeString can't be a PartDesign profile. Converting it to a sketch would
bake the glyph outlines in and break the live `name`. Cutting through Part
keeps the whole chain live: `params.name` → `ShapeString.String` →
`Part::Extrusion` → `Part::Cut`. `ShapeString.Justification`
(`Bottom-Center` / `Middle-Center`, reference `Cap Height`) reproduces
OpenSCAD's `halign` / `valign` without any reference to the glyph extents, so
changing `name` needs no repositioning.

## Makefile

Not added — the existing targets still drive OpenSCAD. To add FreeCAD targets:

```make
FREECADCMD ?= /Applications/FreeCAD.app/Contents/MacOS/FreeCADCmd

BitPresTag-param.FCStd: bitprestag_param.py
	$(FREECADCMD) bitprestag_param.py

fc-stl: bitprestag_param.py
	$(FREECADCMD) bitprestag_param.py -- --stl
```

Headless runs write no view state, so re-saving from `freecadcmd` leaves the
sketches and engraving cutters visible when the file is next opened in the GUI.
Rebuild from inside the GUI, or re-run `_show_only`, if that matters.
